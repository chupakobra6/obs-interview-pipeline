# Adaptive Multilingual Long-Form ASR Selection

Дата: 2026-08-02
Источник: прямая инструкция Игоря и предложенный Яном punctuated-initial-context эксперимент.

## Исходный ввод

Ян сообщил, что на полном русском интервью native timestamped decode с коротким пунктуированным `initial_prompt` дал 1537 слов и 274 знака `. ! ? …` за 35,1 с против 1409 слов, нулевой пунктуации и 36,7 с без prompt. Относительно прежней fixed-chunk расшифровки как серебряного, но не человеческого, референса условный WER снизился с 30,2% до 20,1%, word recall вырос с 86,7% до 94,2%, word F1 — с 86,1% до 89,5%. В предложении prompt используется только как пример пунктуированного предыдущего текста, `carry_initial_prompt=false`, а обычный перенос распознанного контекста между внутренними окнами остаётся включён.

Игорь требует не принимать конкретный удачный вариант заранее, а перебрать содержательно разные архитектурные решения и выбрать лучшее по качеству, производительности и простоте реализации. Итоговый OBS flow должен адаптивно работать как минимум с русским и английским языком, не требовать ручного выбора языка и не размножать публичные профили и настройки. Нужно собрать статистику по вариантам, проанализировать полученный текст, проверить prompt leakage, начало/середину/конец, повторы, паузы, плохой микрофон, технические термины, короткую запись и тишину/шум. Модель `large-v3-turbo-q5_0`, Metal и уже выбранные быстрые decode settings остаются исходной производительной базой; заметное замедление без доказанного выигрыша качества неприемлемо.

Публичная поверхность Harvest должна остаться маленькой: основной Telegram ASR и один OBS long-form режим; третий режим допустим только если у него есть действующий отдельный caller и доказанная необходимость. Все внутренние настройки должны иметь один кодовый источник истины, входить в descriptor/cache identity и не дублироваться в OBS.

## Нормализация

- [ ] сравнить законченные политики, а не отдельные флаги: native baseline, статический style prompt, языково-адаптивный prompt и один динамический bootstrap; multi-chunk рассматривать только если более простые one-request/one-bootstrap решения проиграют;
- [ ] использовать один и тот же `large-v3-turbo-q5_0`, Metal, beam/fallback settings и свежий production-equivalent процесс для сопоставимых прогонов;
- [ ] включить русский и английский corpus, известный ground truth для синтетических edge cases и реальный long-form sample с явно обозначенным silver reference;
- [ ] измерять WER/recall/F1 либо CER там, где есть ground truth, пунктуацию и её распределение по времени, coverage, repetition, prompt leakage, language mixing, latency и архитектурную сложность;
- [ ] выбрать одну адаптивную OBS-политику без ручного language/profile knob;
- [ ] дедуплицировать публичные профили и настройки до реально используемого минимума;
- [ ] обновить Harvest descriptor/cache key и межрепозиторный контракт при изменении transcript semantics;
- [ ] провести current-head integrated rerun и не оставлять benchmark media/transcripts/processes после фиксации агрегированных evidence.
