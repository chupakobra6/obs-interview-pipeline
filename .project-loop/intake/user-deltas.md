### Проверка `max_len=-1` для long-form сегментов

ID источника: `S012`

Исходный ввод:

```text
Установленный whisper.cpp при max_len=0 фактически ограничивает timestamped-сегменты 60 символами. Harvest сейчас max_len вообще не передаёт. Можно явно передавать max_len=-1, чтобы отключить дополнительное символьное разбиение. Это не добавит отсутствующую пунктуацию, но сделает сегменты менее рваными, уменьшит количество бессмысленных переносов и не должно менять набор распознанных токенов. При внедрении нужно доказать структурным сравнением, что нормализованный текст до и после идентичен.

Проверить, объяснить и реализовать только если нет регрессий качества и производительности; показать, что было и что стало.
```

Нормализация:
- [x] проверить точную семантику server default и core wrapping в установленном whisper.cpp v1.9.1;
- [x] провести real-file A/B при одинаковом WAV/decode и единственном отличии `max_len`, используя fresh server process для каждого измерения;
- [x] сравнить exact и Unicode-normalized text, tokens, segments, переносы и runtime;
- [x] менять production только если сегментация действительно улучшается при идентичном нормализованном тексте и сопоставимом времени;
- [x] не выдавать no-op за улучшение качества.

Результат:
- Fresh-process `max_len=0` и `max_len=-1` побайтно совпали по text, normalized text, tokens, segment texts и timestamp bounds во всех четырёх прогонах.
- Оба режима дали 1458 raw words, 9386 chars, 344 строки/сегмента, median 15 и maximum 190 символов на сегмент; это прямо доказывает, что 60-символьный wrap не действует.
- Median inference составил 48.48 s для `0` и 50.86 s для `-1`; выигрыша скорости нет.
- Production-правка отклонена как no-op. Реальная причина коротких строк — native timestamp segmentation, а не `max_len`.
